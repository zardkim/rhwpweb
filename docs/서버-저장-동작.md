# 서버 저장 동작

[파일] 메뉴 아래쪽에 항목이 추가된다. 기존 열기·저장은 그대로 **로컬(PC·모바일)** 이다.

| 메뉴 | 동작 |
|---|---|
| ☁ 서버에서 열기... | 서버 파일 탐색 창. 폴더는 눌러서 들어가고, 문서는 더블클릭(모바일은 탭 → [열기]) |
| ☁ 서버에 저장 | 서버에서 연(또는 서버에 저장한) 문서는 같은 자리에 바로 덮어쓴다. 아니면 '다른 이름으로' |
| ☁ 서버에 다른 이름으로 저장... | 폴더를 고르고 이름 입력 + `.hwp`/`.hwpx`. 같은 이름이 있으면 덮어쓸지 묻는다 |
| 내 계정 · 비밀번호 변경 / 사용자 관리 / 로그아웃 | 메뉴바 오른쪽 👤 버튼과 같다. 계정·관리 화면은 새 탭 |

탐색 창의 맨 위('서버'):

| 항목 | 실제 위치 | 누가 |
|---|---|---|
| 🏠 내 문서 | `files/<사용자>/` (하위 폴더 포함) | 본인만 |
| 🗂 `<이름>` (공유) | `files/mount/<이름>/` | 로그인한 모든 사용자. 삭제는 관리자만 |

- **내 문서는 사용자별**: 각자 자기 파일만 보인다. 다른 사람 폴더로는 갈 수 없다.
- NAS 에서 직접 넣은 `.hwp/.hwpx/.hml` 과 하위 폴더도 그대로 보인다 (`@eaDir`, `#recycle` 같은 시스템 항목은 숨긴다).
- **서버 문서를 편집 중이면 `Ctrl+S` 는 서버에 저장**한다. 로컬 문서일 때는 원래대로 로컬 저장.
- **동시 편집 보호**: 연 뒤에 다른 기기·사람이 같은 파일을 저장했다면 덮어쓰기 전에 묻는다 (함께 편집하는 기능은 아니다).
- 암호가 걸린 문서는 서버 저장을 하지 않는다 (암호가 풀린 채 저장되는 것을 막기 위해) → 로컬 저장 사용.
- 모바일은 로컬 저장이 '다운로드' 뿐이라, 서버 저장을 쓰면 PC 와 같은 문서를 이어서 편집할 수 있다.
- `RHWP_AUTH=request`(compose 기본)에서만 동작한다.

## 다른 파일 기능과의 관계

| 기능 | 서버 저장과의 관계 |
|---|---|
| 저장 / 다른 이름으로 저장 / HWP·HWPX 형식으로 저장 | **로컬**. 서버 문서를 로컬로 저장하면 서버 연결이 끊기고, 그 뒤 `Ctrl+S` 는 로컬 저장 |
| PDF로 저장 | 브라우저 인쇄 창의 'PDF로 저장' → **로컬만**. PDF 는 브라우저가 만들어 앱이 파일을 받을 수 없다 |
| HTML·Word 내보내기 | 로컬 다운로드만 |
| 작업 중 자동 저장 | 편집 후 약 10초 쉬면 **이 브라우저 안(IndexedDB)** 에 복구본을 만든다. 서버로 보내지 않는다. 저장하면 복구본은 지워진다 |
| 창을 닫았다 다시 열기 | 저장 안 한 변경이 있으면 닫을 때 경고, 다시 열면 '문서 복구' 창. 복구한 문서(`X 복구본.hwp`)에서 **☁ 서버에 저장** 을 누르면 원래 서버 파일 `X` 에 이어서 저장할지 묻는다 |
| 최근 문서 | **로컬 파일 전용**. 서버 문서는 ☁ 서버에서 열기 목록이 최근 수정 순이다 |
| 다른 사람이 같은 브라우저로 로그인 | 앞 사람의 자동 저장 복구본·최근 문서·서버 연결 정보를 **로그인 순간 지운다** |

> 자동 저장 복구본은 서버가 아니라 **그 브라우저**에 있다. 기기를 옮겨 이어서 작업하려면 서버에 저장한다.

## 파일 이름·권한

- 파일 이름에 `\ / : * ? " < > |` 와 점(.)으로 시작하는 이름은 쓸 수 없다 (SMB 에서도 보이도록).
- 저장되는 파일은 `PUID:PGID` 소유가 된다.
- 공유 폴더 안 파일의 소유자·권한은 바꾸지 않는다. 권한이 없으면 "쓸 권한이 없습니다", 읽기 전용(`:ro`)이면 "읽기 전용".
