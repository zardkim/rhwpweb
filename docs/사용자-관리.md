# 사용자 관리

## 웹 (관리자 화면 `/rhwp-auth/admin`)

편집기 메뉴바 오른쪽 **👤 버튼 → 사용자 관리** (또는 [파일] 메뉴 아래쪽)에서도 새 탭으로 열린다.

- 사용자 추가 — 비밀번호를 비우면 자동 생성해 **한 번만** 보여준다
- 비밀번호 재설정 · 비활성화/활성화 · 관리자 지정/해제 · 삭제
- 재설정·비활성화하면 그 사용자의 기존 로그인은 **즉시** 끊긴다
- 자기 자신은 비활성화·삭제·권한 해제 불가, 활성 관리자는 최소 1명 유지
- 사용자를 추가하면 `files/<사용자>/` 폴더가 바로 만들어진다 (삭제해도 폴더는 남긴다 — 같은 이름으로 다시 만들면 다시 보인다)
- 사용자 이름은 영문·숫자·`._-` 2~32자, 대소문자를 구분하지 않는다 (`Kim` 과 `kim` 은 같은 사용자 — 폴더가 겹치지 않도록)
- `mount` 는 공유 폴더 자리로 예약된 이름이라 쓸 수 없다

각 사용자는 `/rhwp-auth/` 에서 자기 비밀번호를 바꾸고 로그아웃할 수 있다.

## CLI (관리자 비밀번호를 잊었을 때 등)

```bash
docker exec rhwp-auth rhwp-auth user list
docker exec -it rhwp-auth rhwp-auth user passwd admin        # 프롬프트로 입력
docker exec -it rhwp-auth rhwp-auth user add kim --admin
docker exec rhwp-auth rhwp-auth user disable kim             # enable / admin / unadmin / del
docker exec rhwp-auth rhwp-auth version
```

CLI 도 PUID 사용자로 내려가 실행되므로 DB 파일 소유자가 root 로 바뀌지 않는다.

## 사용자 DB

- `db/users.db` (SQLite, WAL) 와 `db/secret.key`(세션 서명 키). `RHWP_AUTH_SECRET` 을 지정하면 secret.key 대신 그 값을 쓴다.
- 비밀번호는 bcrypt 해시만 저장한다.
- 직접 볼 수 있다: `sqlite3 db/users.db 'select name, admin, disabled, last_login from users'`
  다만 추가·변경은 웹이나 CLI 로 한다 (DB 를 직접 고치면 '관리자 최소 1명' 같은 검사를 건너뛴다).
- 첫 관리자(`RHWP_AUTH_ADMIN_USER`/`_PASSWORD`)는 사용자가 0명일 때만 만들어진다.

## 백업

설치 폴더의 `db/` 와 `files/` 를 Hyper Backup 등으로 백업한다.
`db/` 는 실행 중에도 복사할 수 있지만(WAL), 확실히 하려면 잠깐 멈추고 복사한다:

```bash
docker compose stop rhwp-auth && tar czf rhwp-db-$(date +%F).tgz db && docker compose start rhwp-auth
```
