# 빌드와 배포

## build.sh

```bash
./build.sh                       # GitHub main 최신으로 두 이미지 빌드 (로컬)
./build.sh --push                # + 레지스트리 푸시 (미리 docker login)
./build.sh --web-only --push     # 웹 이미지만 (update.sh 가 사용)
RHWP_REF=v0.9.0 ./build.sh       # 특정 태그
./build.sh --no-fetch            # 소스 갱신 없이 재빌드
```

> ⚠ `build.sh` 기본은 업스트림 **main** 이다. 운영 `latest` 는 정식 릴리스를 따라가므로,
> rhwp-auth 만 바꿨을 때도 `RHWP_REF=<릴리스 태그> ./build.sh --push` 로 하거나, 끝난 뒤 `./update.sh --force` 로 `latest` 를 릴리스 빌드로 되돌린다.

- RHWP 소스는 `~/.cache/rhwp-docker/src` 에 sparse checkout (mydocs·pdf 제외, 프로젝트 폴더 밖).
- 절차는 업스트림 `deploy-pages.yml` 과 같다: `wasm-pack-locked.sh --target web --release` → `npm ci` → `vite build --base=/rhwp/`. 빌드 도구는 최종 이미지에 남지 않는다.
- 빌드 옵션(`--build-arg`): `RHWP_PWA=1`, `RHWP_WITHOUT_AI=1`(AI 도우미 제외), `RHWP_WITHOUT_HWPCTRL=1`, `RHWP_DISABLE_EXTERNAL_WEBFONTS=1`(외부 CDN 웹폰트 차단).
- 이미지 이름은 `IMAGE_NS`(기본 `docker.io/zardkim`) + `rhwpweb` / `rhwpweb-auth`. 다른 레지스트리에 올리려면 `IMAGE_NS=registry.example.com/team ./build.sh --push`.
- 푸시에만 `docker login` 이 필요하다 (`DOCKER_CONFIG` 를 지정하면 그 설정을 쓴다). 받기(pull)는 공개라 불필요.

## 태그 규칙

| 이미지 | 태그 | 올리는 때 |
|---|---|---|
| rhwpweb | `<studio 버전>-<업스트림 커밋 7자리>-r<PKG_REVISION>` 예) `0.9.0-c9095c5-r6` | 패키징(Dockerfile·nginx/·web/)을 바꾸면 `PKG_REVISION` +1 |
| rhwpweb-auth | `auth/VERSION` 예) `0.4.1` | `auth/` 를 바꾸면 올림 |

- **버전 태그는 덮어쓰지 않는다.** `--push` 는 레지스트리에 같은 태그가 있으면 linux/amd64 이미지 digest 를 비교해
  같으면 건너뛰고, 다르면 중단한다 → 번호를 올리고 다시 빌드. (`--force` 로 강제 가능, 비권장)
- `latest` 는 매번 최신 빌드로 옮겨진다.

## 업스트림 새 버전 자동 반영 (update.sh)

```text
[빌드 서버 cron 매일 04:00]  update.sh
   GitHub 최신 정식 릴리스(vX.Y.Z) 확인 ── 이미 반영함 ──▶ 종료
        │ 새 버전
        ▼
   빌드 ─▶ 스모크 테스트(HTTP + 헤드리스 브라우저) ── 실패 ──▶ 푸시 안 함 (latest 그대로)
        │ 통과
        ▼
   Docker Hub 푸시: rhwpweb:<버전>-<커밋>-r<N> + latest 이동

[NAS 작업 스케줄러 매일 05:00]  docker compose pull && up -d
```

```bash
./update.sh --check      # 새 버전 확인만 (있으면 종료코드 10)
./update.sh              # 새 버전이면 빌드 → 스모크 테스트 → 푸시
./update.sh --force      # 이미 반영한 버전도 다시
RHWP_TRACK=main ./update.sh   # 릴리스 대신 main 최신 커밋을 따라감
```

cron (`crontab -e`):

```cron
0 4 * * * /path/to/rhwpweb/update.sh >> $HOME/.cache/rhwp-docker/update.log 2>&1
```

- 기본은 **정식 릴리스(태그 `vX.Y.Z`)만** 따라간다 (업스트림은 대략 월 1회 릴리스, `main` 은 한 달 100건 이상 변경).
- 마지막 반영 상태: `~/.cache/rhwp-docker/last-built` (`<태그> <커밋> r<리비전>`). `PKG_REVISION` 을 올리면 다음 실행 때 다시 빌드한다.
- rhwpweb-auth 는 업스트림과 무관하므로 update.sh 는 웹 이미지(rhwpweb)만 다룬다.
- 결과는 `~/.cache/rhwp-docker/update.log`.

## 스모크 테스트 (`scripts/smoke-test.sh <이미지>`)

임시 컨테이너를 인증 없이 띄워 `/healthz`·`/rhwp/`·`rhwp_bg.wasm`·index 가 참조하는 모든 파일을 확인하고,
Playwright(헤드리스 Chromium, `scripts/smoke.mjs`)로 에디터가 빈 문서를 여는지(WASM 초기화), 페이지 오류가 없는지,
확장 메뉴(`ext:cloud-*`, `ext:account-*`)와 👤 버튼이 붙었는지 본다. 하나라도 실패하면 **푸시하지 않는다**.

## latest 를 이전 태그로 옮기기

`~/.cache/rhwp-docker/last-built` 는 그대로 두고(다시 빌드하지 않음):

```bash
docker buildx imagetools create -t zardkim/rhwpweb:latest zardkim/rhwpweb:<이전 태그>
```
