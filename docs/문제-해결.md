# 문제 해결

## 저장한 파일·DB 가 NAS 폴더에 안 보일 때

**관리자 화면(`/rhwp-auth/admin`) 맨 위 '저장 위치 점검'** 이 실제 저장 위치를 보여준다.
NAS 쪽 경로는 디스크 안 경로로 보인다 (`/volume1/docker/rhwp/files` → `/docker/rhwp/files`).

| 점검 결과 | 원인 | 해결 |
|---|---|---|
| Docker 볼륨 '…_rhwp-files' 에 저장되고 있습니다 | 컨테이너가 예전 `docker-compose.yml`(볼륨 방식)로 만들어져 있음. 예전 compose 는 `.env` 의 `RHWP_DB_DIR`/`RHWP_FILES_DIR` 를 읽지 않는다 | [이전 버전에서 옮기기](이전-버전에서-옮기기.md) |
| Portainer 스택의 상대 경로 | `./db`, `./files` 가 Portainer 내부로 잡힘 | 스택 환경변수 `RHWP_DB_DIR`, `RHWP_FILES_DIR` 를 `/volume1/…` 절대 경로로 |
| 마운트되어 있지 않습니다 | compose 의 volumes 가 빠짐 | 새 compose 확인 |

compose·`.env` 를 고친 뒤에는 **컨테이너를 다시 만들어야** 한다 (`docker compose up -d`, Container Manager 는 중지 → 빌드). 재시작만으로는 바뀌지 않는다.

명령으로 확인:

```bash
docker compose ls                                    # 어느 폴더의 compose 로 떠 있는지 (…/compose/N/ 이면 Portainer)
docker inspect rhwp-auth -f '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
docker exec rhwp-auth rhwp-auth version              # 0.4.1 이상
docker logs rhwp-auth 2>&1 | grep '저장 위치'
```

## "서버 저장소를 사용할 수 없습니다"

폴더에 쓸 수 없으면 rhwp-auth 는 멈추지 않고 서버 저장 기능만 끈다. 로그에
`⚠ /files 에 쓸 수 없어 서버 저장 기능을 끕니다 (uid=…)` 가 남는다.
→ `PUID/PGID` 와 폴더 권한을 확인한다. Synology 공유폴더는 ACL 때문에 소유자 변경이 거부될 수 있다.
그때는 DSM 공유폴더 권한에서 PUID 사용자에게 읽기/쓰기를 준다.

## 공유 폴더가 안 보인다

- `docker logs rhwp-auth 2>&1 | grep '공유 폴더'` 에 이름이 나오는지 본다.
- 컨테이너 쪽 경로가 정확히 `/files/mount/<이름>` 인지, override 파일이 읽혔는지(Portainer 는 안 읽음) 확인한다.

## 관리자 비밀번호를 잊었다

[사용자 관리](사용자-관리.md) 의 CLI: `docker exec -it rhwp-auth rhwp-auth user passwd admin`

## 앱이 열리지 않는다 (500)

인증 서비스(rhwp-auth)가 내려가 있으면 앱은 열리지 않는다(안전한 쪽으로 실패). `docker compose ps`, `docker logs rhwp-auth` 확인.
