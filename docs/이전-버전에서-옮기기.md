# 이전 버전(Docker 볼륨)에서 옮기기

rhwp-auth 0.2.x 때의 `docker-compose.yml` 은 사용자와 서버 저장 문서를 Docker 볼륨
(`<프로젝트>_rhwp-auth-data`, `<프로젝트>_rhwp-files`)에 저장해 NAS 폴더에서 보이지 않는다.
**그 compose 는 `RHWP_DB_DIR` / `RHWP_FILES_DIR` 를 읽지 않으므로 `.env` 만 고쳐서는 바뀌지 않는다.**
관리자 화면 '저장 위치 점검' 에 `Docker 볼륨 '…_rhwp-files'` 가 보이면 이 경우다
(앞부분이 compose 프로젝트 이름 — Container Manager 프로젝트나 Portainer 스택 이름).

1. 설치 폴더(예: `/volume1/docker/rhwp`)에 **새 `docker-compose.yml`, `.env`, `scripts/migrate-volumes.sh`** 를 둔다.
   `.env` 의 `RHWP_DB_DIR`, `RHWP_FILES_DIR`, `PUID`, `PGID` 를 확인한다.
2. SSH 로 옛 데이터를 새 폴더로 옮긴다 (옛 볼륨은 지우지 않으므로 되돌릴 수 있다):
   ```bash
   cd /volume1/docker/rhwp
   sudo sh scripts/migrate-volumes.sh           # 볼륨을 자동으로 찾는다. 여러 개면: … migrate-volumes.sh rhwpweb
   ```
   컨테이너 rhwp·rhwp-auth 를 멈추고 지운 뒤, 볼륨 내용을 `.env` 의 db·files 폴더로 복사하고 소유자를 PUID:PGID 로 맞춘다.
   db 폴더에 이미 `users.db` 가 있으면 덮어쓰지 않고 멈춘다.
3. **컨테이너를 새 compose 로 다시 만든다.** 재시작만으로는 바뀌지 않는다.
   - SSH: `cd /volume1/docker/rhwp && sudo docker compose up -d`
   - Container Manager: 옛 프로젝트(예: `rhwpweb`)를 **삭제**하고 설치 폴더를 경로로 새 프로젝트를 만들거나
     ("기존 docker-compose.yml 사용"), 옛 프로젝트의 YAML 을 새 내용으로 바꾼 뒤 **빌드**한다.
   - Portainer: 스택 편집기의 내용을 새 compose 로 바꾸고, 환경변수에 `RHWP_DB_DIR`·`RHWP_FILES_DIR` 를 절대 경로로 넣은 뒤 **Update the stack**.
4. 관리자 화면 '저장 위치 점검' 이 모두 `정상` 이고 NAS 폴더에 `db/users.db`, `files/<사용자>/` 가 보이는지 확인한다.
5. 문제없으면 옛 볼륨을 지운다: `sudo docker volume rm rhwpweb_rhwp-auth-data rhwpweb_rhwp-files` (이름은 스크립트가 알려준 것)

- 옛 `users.json` 은 첫 실행 때 자동으로 `users.db` 로 옮겨진다(`users.json.imported`). 비밀번호·관리자 여부와 **기존 로그인 상태도 그대로** 유지된다.
- 옛 compose 를 그대로 두고 이미지만 새 버전이 되어도 동작은 한다. 다만 계속 볼륨에 저장되어 NAS 폴더에서는 보이지 않는다.
